# Independent novelty review (literature scope)

Review date: 2026-09-23 UTC  
Reviewer: independent Codex reviewer agent, read-only review  
Review scope: initial literature review plus follow-up reviews after the official AICAS 2026 proceedings papers and StreamTensor full text were obtained. No FPGA design, frozen code commit or hardware data existed to audit. Reviewer did not modify the workspace, run tests or access the board.

## Conclusion

The broad PhaseMap-VLM novelty framing is **not supported**. Stage-dependent dataflow/kernel selection, FPGA VLM phase offload, cross-stage resource sharing, PS–PL data-movement optimization, persistent GDN state, and liveness-driven buffer reuse each have direct or adjacent prior art. The only defensible next step is a narrow empirical question: for a frozen KV260 software stack, fixed MiniCPM-V checkpoint and numerical/preprocessing contract, does an explicit trace-driven joint plan beat equally tuned two-overlay, shared-resource, and movement-optimized static controls on measured full-request image-QA latency without exceeding a registered quality tolerance? This remains a go/no-go hypothesis, not a contribution claim.

The follow-up review read the complete five-page official proceedings papers for VersaVLM (printed pp. 436–440), UniVLM (pp. 451–455), single-request VLM optimization (pp. 456–460), and Memory-Centric VLM Deployment (pp. 461–465). VersaVLM is a direct KV260/SmolVLM2 phase-specialized, two-bitstream VLM counterexample; UniVLM covers cross-stage ViT/LLM matrix sharing and buffer reduction; Memory-Centric VLM covers KV260/llama.cpp PS–PL movement/layout/overlap; and the single-request paper contributes adjacent GPU runtime/profiling precedent. Source hash and page mapping are recorded in `source_access.md`; the source file stays outside the repository.

A further independent follow-up read StreamTensor §§1, 3.1–3.2, 4, 5.1–5.3 and 6 from the complete MICRO 2025/arXiv v2 paper (printed pp. 201–216). Its stream-layout type system, inserted layout converters, compiler-generated DMA/host runtime, tile/fusion/resource exploration and LP-based FIFO sizing overlap even the candidate “trace-driven joint plan.” Its actual BRAM/URAM placement is simple size-priority, not K26 bank/port/lifetime allocation; its fusion plan is implemented as a topological greedy heuristic, not a global optimum. It uses U55C/HBM and is not a KV260 VLM measurement. See `notes/streamtensor.md`.

This materially narrows the surviving question. It is no longer “can phase-specific execution help?” Even “trace-driven joint plan” is too broad because StreamTensor already provides compiler-level graph/fusion/resource exploration and host runtime management. The candidate should be treated as an engineering go/no-go unless a specific new decision variable and policy are isolated—for example, request-DAG overlay choice jointly constrained by measured K26 bank/port allocation, live-range residency, and board-measured PS–PL plus bitstream-transition cost. A different VLM checkpoint or FPGA by itself does not restore novelty.

## Key counterexamples

- **MEADOW (MLSys 2025):** the reviewer read the full paper, focusing on architecture, TPHS/GEMM dataflow and experiments. It uses token/head scheduling and data packing to reduce memory movement, with prefill/decode experiments on ZCU102. This defeats a generic claim that phase-specific LLM dataflow is new, but does not give a directly comparable KV260/VLM result. [Official paper](https://proceedings.mlsys.org/paper_files/paper/2025/file/259a5df46308d60f8454bd4adcc3b462-Paper-Conference.pdf)
- **TeLLMe (FPGA 2026):** the reviewer read the relevant full sections in the v2 preprint, not the final ACM paper. It runs BitNet 0.73B on KV260, distinguishes prefill/decode and keeps the PS LM head in its full-request boundary. This defeats a broad claim that KV260 lacks phase-specialized end-to-end LLM work; its ternary model prevents direct performance comparison with MiniCPM-V. [Author preprint](https://arxiv.org/html/2510.15926v2), [FPGA proceedings record](https://zenodo.org/records/18294432), [ACM DOI](https://doi.org/10.1145/3748173.3779191)
- **Hummingbird (ICCAD 2025):** the reviewer read the preprint's optimization/platform/experiment sections and verified the IEEE record. It is an LLM accelerator on KV260 with W4 weights and INT8 KV under a particular short-context decode setup. It is not a VLM full image-QA latency baseline. [Preprint](https://arxiv.org/html/2507.03308v2), [IEEE record](https://ieeexplore.ieee.org/document/11241002/)
- **ReCoVLM (FCCM 2026):** at the date of this original review the primary text was unavailable, so the reviewer used only its official title/program as a counterexample. A later user-provided full publisher PDF now verifies the stage split, token-normalization, KV-transfer, static-cache and bank-group mechanisms. This later evidence was read and added by the project agent, not independently re-reviewed; see the dated update below and [`notes/recovlm.md`](notes/recovlm.md). [Official accepted-paper list](https://www.fccm.org/accepted-paper-list-2026/), [official program](https://www.fccm.org/past/2026/fccm-26-program/)
- **LCMM/DNNK (DAC 2019):** the review confirms that feature-tensor interference graphs, global liveness, buffer reuse, prefetch and splitting are established FPGA DNN memory-management techniques. [DOI](https://doi.org/10.1145/3316781.3317875), [full text](https://ceca.pku.edu.cn/docs/20190924081919448582.pdf)
- **MLIR-AIE:** AMD/Xilinx documentation already offers bank-aware allocation and hard bank pins for AI Engine local buffers. This is not K26 PL allocation evidence, but defeats an unqualified claim that bank-aware allocation is itself new. [Allocator documentation](https://xilinx.github.io/mlir-aie/dev/programming_guide/core_data_memory/)
- **Persistent-State Dataflow:** state residency and recurrent-state fusion have a concrete FPGA precedent on U55C. The published table separates a placed/routed H_iter=2 result from a faster estimate and an unroutable case. [Preprint](https://arxiv.org/html/2603.05931v1), [IEEE DOI](https://doi.org/10.1109/IPDPSW71298.2026.00064)
- **TRINE:** the reviewer read the mechanisms and experiments; it uses runtime dataflow modes and DAG scheduling for TinyCLIP/MDETR/MissionGNN rather than autoregressive VLM image QA. [Preprint](https://arxiv.org/html/2603.22867v1)
- **StreamTensor (MICRO 2025):** full paper read. An MLIR compiler encodes stream layouts in `itensor` types, inserts ping-pong layout converters, explores tiling/fusion/resource allocation, sizes FIFOs with token-behavior models and LP, and generates DMA plus a host transfer/execution runtime. Experiments are on-board U55C/Vitis 2024.1, W4A8, with 41MB on-chip memory; intermediate memory after layer fusion is reported at 14.8–16.8% of unfused. This is a direct compiler/dataflow/fusion and runtime prior; it is not a K26 bank/port or VLM image-QA measurement. Its fusion is a greedy topological heuristic, not globally optimal. [Full text](https://arxiv.org/html/2509.13694), [author publication page](https://hanchenye.com/publications/papers/)

## Required strongest comparison

B3 should be a tuned static phase-specific plan, not a weak all-GEMM or single-mode baseline. Use the same model, quantization, preprocessing, board, bitstream/resource budget, driver and full-request boundary. Permit static per-phase kernels, legal liveness reuse and bank-aware placement; allocate similar tuning effort to PE count, tile, banks, DMA, prepacking, double buffering and PS threads. Compare both same-bitstream schedule-only and equal-resource hardware variants where possible.

For the specific AICAS counterexamples, include these mechanism families where feasible: (1) two phase-specialized overlays with the transition time charged, as in VersaVLM; (2) one time-multiplexed ViT/LLM matrix resource with streamed intermediates, as in UniVLM; and (3) matrix-level dispatch, tiled data layout, multi-channel movement and prefetch, as in Memory-Centric VLM. The movement and fusion mechanisms are composable controls: do not leave Memory-Centric or StreamTensor-style layouts/fusion available only to the proposed system. Include a tuned best-of-static combination/oracle over the legal shared, phase-overlay and movement/fusion options, and charge any request-level selector cost. These are project-local controls, not reproduction claims. The UniVLM paper omits prompt/output lengths and request-level TTFT/latency, while its resource ablation excludes interface logic; the Memory-Centric contest and extended-build prefill figures also have different offload scopes. Do not use those reported values as direct numeric targets.

For ReCoVLM, also include token compression followed by fixed two-shape normalization when the same stage is being compared, and charge its filtering/merge overhead under a matched quality contract. Give static KV sink/ring residency and any applicable expert burst/bank-group layout to the controls. ReCoVLM's GPU-only and FPGA-only end-to-end baselines have different stage coverage, so its reported system result is not a matched numerical baseline for this project.

Count end-to-end latency, TTFT, decode latency, energy/power, output quality, traffic, stalls and all data movement. Do not compare performance numbers from different boards/models or claim reproduction of the prior papers.

## Falsification conditions

Reject the proposed method if any of these hold:

1. Static phase tuning performs as well or better when boundary costs are included.
2. DMA, layout conversion, dispatch or synchronization erases the isolated kernel gain.
3. The method's gain appears only against a deliberately weak schedule/allocator.
4. Better bank use does not lower full-request latency, external traffic or measured stalls.
5. The accelerated phase is too small a fraction of the request to beat the Amdahl bound.
6. Output quality changes beyond the pre-registered tolerance.
