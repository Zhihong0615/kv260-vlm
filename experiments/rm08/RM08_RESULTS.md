## SSH execution package and runner readiness

- The target package was rebuilt from the frozen RM07 bitstream and staged to
  `/tmp/rm08-deploy/kv260-rm07-bounded-k16` over SSH. Board-side hashes match:
  `.bit.bin` `b8ba3e53…9ddfbc60`, `.dtbo` `4fca210a…7c052d2`, and
  `shell.json` `802dbc8b…7895c344`.
- All nine early/middle/late real-tensor files were copied to the board and
  their SHA-256 hashes match the local files. The full hashes are recorded in
  `evidence/real_tensor_hashes_20260925.txt` and
  `evidence/target_compile_and_stage_20260925.log`.
- `ffn_down_bench.c` compiled on the board against its installed XRT 2.13 API
  with `-Wall -Wextra -Werror`. The binary uses three XRT BOs with 408 total
  CMA pages (W 269, X 135, Y 4). It packs directly into the mapped staging BOs;
  HLS accesses those BOs through HP0. Thus `xclSyncBO` time is reported as
  cache-sync time, while actual PL DDR traffic occurs during kernel commands.
- The APM global clock counter is sampled at each HLS command boundary and
  calibrated against monotonic wall time. The APM is configured at runtime for
  W/X read-byte and Y write-byte counters on its three monitor slots. Reported
  command cycles include the small AXI-Lite start/done observation interval;
  they are board measurements, not HLS schedule projections.
- The board scripts are staged: `first_load_smoke.sh` arms a 180-second restore,
  loads the app, exercises the no-pointer AXI-Lite ABI probe, then restores the
  starter-kit; the benchmark script arms a 900-second restore and performs
  three real single calls, five-call repetitions for each extent, and a
  35×N=1120 plus 100×N=280 representative-tensor schedule replay. The latter
  is explicitly not all 27 distinct layer payloads.
- Direct SSH reached the board, but `sudo` requires interactive authentication.
  The elevated entrypoint has not run; no RM08 image has been loaded and no
  system firmware directory has been changed. The user must launch
  `ssh -tt kria 'sudo bash /tmp/rm08-deploy/ssh_entrypoint.sh'` in their own
  terminal and enter the board password there. No password is needed in chat.

Source and staging evidence: `evidence/target_compile_and_stage_20260925.log`.
