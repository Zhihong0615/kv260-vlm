# RM08 flat-app package

The package is generated by `experiments/rm08/source/build_flat_app.sh` from
the SHA-pinned RM07 routed bitstream. It follows the KV260 starter-kits
`XRT_FLAT` package layout and does not modify boot firmware, QSPI, or SD.

Install the generated directory's three runtime files under:

```text
/lib/firmware/xilinx/kv260-rm07-bounded-k16/
```

Then the starter-kit app manager should expose the application as
`kv260-rm07-bounded-k16`. The `kv260-rm07-bounded-k16.dtsi` overlay enables
AFI access for HPM0/HP0 and maps the AXI performance monitor and HLS control
registers as UIO devices using the board's existing `uio_pdrv_genirq` binding.
It declares HLS compatible/version `xlnx,vision-ffn-down-tile-1.0`.

The RM07 control block has no dedicated immutable IP-ID register. The smoke
probe will therefore check the UIO name/compatible version, AP_CTRL readback,
and a safe invalid-task return signature (`-4`) before any memory pointers or
DMA transactions are issued. That signature exercises the HLS AXI-Lite
register path without touching DDR.

Buffer memory uses the installed XRT 2.13 `xclAllocBO` API. The returned BO
properties expose the physical address used by HLS m_axi; `xclMapBO` maps the
same BO to userspace and `xclSyncBO` performs cache synchronization. A
1,671,168-byte probe returned paddr `0x37f00000`; CMA allocation accounting
increased by exactly 408 pages and the sync round trip passed. See
`evidence/xrt_bo_probe_20260925.log`.

Rollback commands after loading, if SSH remains available:

```bash
sudo xmutil unloadapp
sudo xmutil loadapp k26-starter-kits
```

These commands have not yet been run on this board. SSH currently has
passwordless sudo only for `xmutil listapps`; load/unload requires an
interactive sudo authentication. No independent UART path is currently
available, so no bitstream has been loaded yet.
