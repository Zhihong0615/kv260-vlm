# Research go/no-go

> **RM10 decision (2026-09-26): `GO_RECURRENCE_ARCHITECTURE` as a measured
> feasibility result; paper novelty remains unproven.** The corrected
> same-precision ten-bank engine has K-loop II=1 versus the strong RM09 static
> engine's II=5. It passed C/RTL co-simulation, the frozen numeric gate on
> three real FFN-down tensors, and full-system route at 100 MHz. KV260 kernel
> throughput rose from approximately 3.85 to 4.76–4.78 GMAC/s. In the most
> comparable same-runtime QID37804 request, RM10 took **504.24 s** versus
> **519.39 s** for static (1.030×, 15.15 s saved); the 135-call FFN-down
> family took **83.082 s** versus **99.631 s** (1.199×). The family-only
> substitution predicts 502.841 s, leaving a +1.399 s whole-request residual.
> Both requests produced `G`, used 135 PL calls with 10 expected CPU fallbacks,
> and restored `k26-starter-kits`. The RM10 request still had 5,838 versus
> 4,068 major faults and 165,016 versus 76,840 filesystem input blocks, so
> this one better-matched run supports a practical gain but is not a
> population-level latency estimate. Its read-only CMA sample fell as low as
> about 0.5 MiB with no XRT allocation failure; bounded buffers had already
> been allocated. The prior two RM10 request walls (524.42 and 517.10 s) were
> more cache-confounded and are retained as evidence, not averaged into the
> matched comparison. The first five-bank image was invalidated before load.
> Generic multi-accumulator interleaving and reduction trees are prior art;
> no paper-method novelty is claimed from II=1 alone. See RM10 board evidence
> in `experiments/rm10_boardprep/evidence/`.

> **Latest stage decision (RM09, 2026-09-25): `NO_NOVELTY_YET`.** The strong
> static K16 FFN-down engine now covers observed MiniCPM-V transformer extents
> on one 100 MHz KV260 bitstream. Three complete requests have real PL calls
> and matching answers. With the same runtime binary for each RM09 CPU/PL
> pair, QID38299 improved from 368.51 to 299.14 s (1.232×) and QID35419
> from 822.35 to 652.32 s (1.261×); the RM08 QID37804 result was 668.35 to
> 522.34 s (1.280×). The broader extent contract did not change II=5 or the
> K16 datapath, and no distinct architecture mechanism has passed a strong
> static comparison. See [RM09 milestone results](../experiments/rm09/RM09_MILESTONE_RESULTS.md).

Current decision: **keep RM09 static as the strong comparison baseline and
retain RM10 recurrence decoupling as a viable architecture candidate. P3
paper-method development remains `NO_GO_NOW` until the candidate is shown to
be distinct from established interleaving/reduction techniques.** The RM08
decision below is historical, not the current novelty decision.

> **Historical stage decision (RM08, 2026-09-25): `GO_VLM_INTEGRATION` confirmed.** The real KV260 MiniCPM-V QID 37804 request completed in **522.34 s** with 135 actual transformer FFN-down PL calls, 10 explicit out-of-scope CPU fallbacks, unchanged answer `G`, and successful starter-kit restore. The frozen four-thread CPU-only request took 668.35 s: **1.280× end-to-end speedup**, 21.85% lower wall time. The 135 PL calls took 99.667 s versus 250.124 s CPU family time (2.510×). ## Reasons

1. **No contribution has passed the novelty gate.** Independent review rejects the broad PhaseMap-VLM framing. The remaining trace-driven plan is an empirical engineering question, not a method claim; StreamTensor, direct KV260 VLM papers, GLITCHES, LUT-LLM, and now the full ReCoVLM paper substantially narrow it. GLITCHES/ReCoVLM provide phase handoff, explicit KV movement, and heterogeneous control precedents; LUT-LLM provides a fixed-design dual-phase/port-planning precedent, all under different hardware and model contracts. A new fixed-bitstream candidate screen asks whether a per-job GEMM/GEMV mode choice can improve over an equally tuned static phase/shape table. In the currently observed `N=1` versus `N=60–70` classes, that table can make the same obvious choice; the pinned-runtime audit also confirms node dimensions are available before backend allocation, so shape-only lookup is a strong static control. No incremental policy is supported yet. A first-node integration screen retains Q4_K `N=70` for numeric/interface tractability and identifies vision F16 as a later performance candidate only after board CPU and PL measurement; neither creates a new method. The separate full-overlay switch draft is retained as a rejected main-method candidate/comparator screen. The AICAS Grand Challenge proceedings paper adds a SmolVLM2/KV260 baseline profile and a qualitative synthesis of three leading FPGA-track plan families; it is prior-art context, not a comparable MiniCPM-V result. ReCoVLM directly covers FPGA–GPU VLM stage assignment, two-shape visual-token pruning, KV transfer reduction, static sink/ring cache, CPU LM-head/sampling, and MoE bank-group mapping. See [`independent_novelty_review.md`](../literature/independent_novelty_review.md), [`transfer_hypotheses.md`](../literature/transfer_hypotheses.md), [`p3_candidate_decision_fixed_bitstream_draft.md`](../spec/p3_candidate_decision_fixed_bitstream_draft.md), [`vision_vs_q4_pl_mvp_screen.md`](../spec/vision_vs_q4_pl_mvp_screen.md), [`notes/p1_followup_20260923.md`](../literature/notes/p1_followup_20260923.md), [`notes/recovlm.md`](../literature/notes/recovlm.md), and [`runtime_shape_visibility_audit_20260923.md`](../spec/runtime_shape_visibility_audit_20260923.md).
2. **The CPU baseline now has three request-local exclusive host timelines and two allocator-plan event checks, but not a hardware-design profile.** TextVQA dev50 supplies image-QA quality and end-to-end host timing. Four matched metadata requests have complete host buffer offsets/extents and independently checked view/bounds evidence. Their two later requests have equal vision/image-prefill local peak medians but different per-window maxima; a separate 12-trace shape audit found equal graph-window counts with different matrix widths and nominal arithmetic work. Zero-extent nodes remain graph observations, not timed kernels. A copied CLI partitions online request wall after model setup into adjacent spans for qids 37804, 38299 and 35419, representing five, three and seven image-encoder calls respectively; all 18 ordinary/timed processes matched frozen answers, and all nine traces passed direct raw adjacency checks. The vision/projector API remains combined, and three selected development requests do not establish population phase shares. Direct gallocr event probes for qid37804 and qid38299 show the disputed image `node_0`/residual shared offset is a cached text-plan assignment to a graph node with zero consumers, not a newly measured image-graph free/in-place event. An independent reviewer recomputed the virtual plan, application mapping and callback edges. This resolves those two host cases, but qid37852/38169 and other shapes are not event-checked, and the pair gives no new allocator opportunity. Physical occupancy, traffic, actual K26/PS–PL costs, broad eligible-op elapsed distributions and frozen numerical/quality criteria remain unknown. Selected adjacent-sentinel node timing still includes dispatch/synchronization and is not a broad cost model.
3. **The reboot and immediate CMA resource gate are resolved; board inference remains blocked by separate review gates.** After the user-approved normal reboot, Wi-Fi SSH returned under new boot ID `2a931c48-99ad-4a3f-b3e1-f42634597098`; the reboot marker is absent, the kernel is `5.15.0-1027-xilinx-zynqmp`, APT services are inactive, PackageKit reports `ao 0`, Jupyter is active with no jobs, `xmutil` reports `k26-starter-kits` active, and `xbutil examine` reports the KV260 device ready. Three interval-spaced snapshots show `CmaFree=1,014,300 KiB` each, above the fixed 700,000 KiB floor; `MemAvailable` was 3.34/3.35/3.34 GiB and swap stayed 0. The cause of the earlier low CMA remains unknown, and no VLM inference was run. Current-SHA independent runner/parser review, synthetic ALPHA proof and an owner window for inference are still missing. Do not use the user-owned terminal. Full evidence is in [`board_reboot_cma_resolution_plan_20260923.md`](../handoff/board_reboot_cma_resolution_plan_20260923.md) and `experiments/raw/kv260_reboot_issue_resolution_20260923/`.

## Conditions to reconsider P3

- Expand selected target timings beyond the current four token-decode and two image-prefill development requests, validate graph-local liveness/allocation assumptions with explicit alias limits, and determine whether more adjacent-sentinel samples materially improve a candidate cost model. Three vision shapes, one image-prefill shape and one token-decode shape are sampled; a broad cost profile and payload-derived scale/min distributions across all Q4_K/Q6_K tensors are not.
- Treat the `node_0`/residual same-slot pair as cached-plan behavior for qid37804 and qid38299, not as a new allocator optimization. If allocator work remains a candidate, confirm remaining request shapes and find a different validated live interval or physical port conflict before claiming benefit. Round03–Round06 offsets/extents and the two gallocr event probes are host virtual evidence; later ARM/KV260 memory evidence remains separate. Keep logged capacities distinct from RSS and do not add overlapping categories.
- Identify one concrete candidate decision variable that survives comparison against equally tuned static shared-resource, two-overlay, and movement/fusion plans. Charge layout, dispatch, transfer, synchronization and overlay transition costs.
- Continue the host numeric contract from the payload-level oracle in [`numeric_spec.md`](../spec/numeric_spec.md): establish actual board backend dispatch when authorized, freeze float tolerances and model-quality budget, and record supported-shape/fallback behavior. Then freeze preprocessing, request boundary, candidate controls and stopping/falsification rules. Retain the invalid pre-initialization dot report as a failure record; Round 06 is the final locked host run, and the x86 CPU Q8 entrypoint match is not an independent implementation check.
- Before any first research-image or bitstream load, record the exact image/design, slot, known-good identifier, authorized operation, board ownership window, verified rollback steps and the applicable stage-specific approval. Current permission covers read-only listing only.

If no candidate separates from the tuned static envelope beyond model uncertainty, stop method implementation and preserve a negative engineering result. Reassess this decision when the trace, feasibility model and safe board plan are reviewable.
